# 01.5 — Design Psychology

> ATLAS Design Psychology Constitution · Version 1.0

## Purpose

Design is not decoration; it is decision making. Every screen reduces uncertainty, every interaction reduces cognitive effort, and every component helps people complete a task with confidence. ATLAS guides users; it does not try to impress them.

## Principles

### The golden rule

Users should never think, “What do I click?” They should think, “That was easy.”

### Cognitive load and progressive disclosure

Attention is limited. Reduce choices, clutter, reading, scrolling, and uncertainty. Never reveal everything at once: show the simple decision first, then progressive details. An internship card can start with company, role, location, and meaningful status, then disclose benefits, assessment, accommodation, transport, documents, and timeline when requested.

### Recognition over recall

Users recognize; they should not have to memorize. Use clear labels, familiar icons, breadcrumbs where hierarchy requires them, visual grouping, and persistent navigation. Follow familiar patterns—innovation belongs in the future allocation engine, not basic navigation.

## Rules

- Apply Jakob’s Law: use predictable layouts and common interactions; never reinvent basic UI patterns.
- Apply Hick’s Law: emphasize one primary action, reduce visible choices, and place advanced actions in secondary menus. Do not present six equally important buttons.
- Apply Fitts’ Law: buttons, search, menus, and selection controls need comfortable targets; never rely on tiny click areas.
- Apply Miller’s Law: group dashboard cards, filters, statistics, and navigation into meaningful clusters; never show dozens of simultaneous metrics.
- Apply Gestalt principles: group related information, separate unrelated information, and prefer spacing before borders.

## Standards

Visual hierarchy must make primary, secondary, supporting, and background content obvious. Typography establishes hierarchy; spacing reinforces it; color supports it; motion only directs attention. Buttons, links, cards, and menus use concrete information scent: prefer “View internship”, “Upload resume”, or “Track application” to vague “Continue”.

Trust is built by clear language, predictable layouts, verified badges, progress indicators, transparent explanations, readable type, and consistent spacing. It is lost through unexpected popups, inconsistent behavior, hidden information, overloaded pages, and unclear errors.

Prevent mistakes before correcting them: disable impossible actions with an explanation, show requirements early, and validate incrementally where that reduces costly errors. Never let someone complete a long form only to learn every issue at submission.

## Examples

An empty applications table states why it is empty, offers the next action, and explains how to continue; it is never a blank grid. A loading state uses a skeleton or meaningful progress message and does not freeze the interface. A success state celebrates quietly with confirmation and a next step.

Error copy guides recovery and never blames the user. Prefer “Please enter a valid Aadhaar-linked mobile number” over “Invalid input.”

## Best practices

Dashboards optimize for efficiency: information density is acceptable, visual noise is not. Common actions should require no more than three deliberate interactions where feasible; search should be easy to find and navigation stable.

Landing pages explain, inspire, build trust, and tell the story; they do not carry task-completion workflows. Government UX optimizes for clarity, transparency, fairness, accessibility, reliability, and trust—not novelty. Premium UX means fast, simple, reliable, comfortable, consistent, and thoughtful.

Apply [01 Brand](01-Brand.md), [02 Design System](02-Design-System.md), [06 Motion](06-Motion.md), and [07 Accessibility](07-Accessibility.md). The ATLAS UX flow is: **Trust → Understanding → Confidence → Action → Success**.

## Future expansion notes

Add task-flow research, usability benchmarks, content guidelines, interaction heuristics, low-bandwidth flow patterns, regional-language usability studies, and design-review checklists.

Every design decision must answer: does it reduce cognitive effort, increase trust, and help the user complete their goal? If not, it should not exist.
