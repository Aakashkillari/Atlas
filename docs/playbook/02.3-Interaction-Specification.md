# 02.3 — Interaction Specification

> ATLAS Engineering Playbook · Version 1.0

---

# Purpose

This document defines the interaction language of ATLAS.

Interaction is the conversation between the system and the user.

Every interaction should reduce uncertainty, communicate system state, and guide users toward successful task completion.

Users should never ask

"What just happened?"

Every interaction should answer that question automatically.

This specification is mandatory for every engineer and every AI coding assistant contributing to ATLAS.

---

# Interaction Philosophy

Interaction should feel

- Immediate
- Predictable
- Accessible
- Responsive
- Calm
- Intentional

The interface should never surprise users.

The user should always remain in control.

---

# Core Principles

Every interaction must satisfy at least one objective.

• Communicate state

• Confirm action

• Guide attention

• Reduce cognitive effort

• Prevent mistakes

• Encourage confidence

If an interaction serves none of these objectives, it should not exist.

---

# Interaction Hierarchy

Interactions are prioritized in the following order.

1. Accessibility

2. User Feedback

3. Clarity

4. Performance

5. Motion

6. Visual Delight

Visual delight should never reduce usability.

---

# Mouse Interaction

Mouse users should receive immediate visual feedback.

Hover

↓

Focus

↓

Click

↓

Confirmation

Every clickable element should clearly communicate that it is interactive.

Never require double-clicking.

---

# Keyboard Interaction

Every workflow must be fully operable without a mouse.

Support

Tab

Shift + Tab

Enter

Escape

Arrow Keys

Space

Shortcuts where appropriate.

Dialogs must trap focus.

Closing dialogs restores focus to the triggering element.

---

# Touch Interaction

Touch targets

Minimum

44×44 pixels

Interactive elements require sufficient spacing.

Avoid interactions requiring precision.

Never depend on hover.

---

# Hover Behaviour

Purpose

Indicate possibility before commitment.

Hover should

Increase elevation

Increase contrast

Reveal secondary actions

Never

Move layouts

Trigger navigation

Reveal critical functionality

Hover animations

120–150ms

ease-out

Hover interactions must gracefully degrade on touch devices.

---

# Focus Behaviour

Purpose

Support keyboard users.

Every focusable element requires a visible focus indicator.

Focus must never rely solely on color.

Focus order should follow reading order.

---

# Active Behaviour

Purpose

Communicate immediate acknowledgement.

Pressed states should occur instantly.

Avoid delayed visual feedback.

---

# Selected Behaviour

Selected items should remain visually distinct.

Selection should persist until explicitly changed.

Support

Mouse

Keyboard

Touch

---

# Disabled Behaviour

Disabled controls should explain why they are unavailable whenever practical.

Avoid disabling primary workflows without explanation.

Never silently disable essential actions.

---

# Loading Behaviour

Loading should reassure users.

Never leave users wondering whether the system is working.

Hierarchy

Under 200ms

No loading indicator required.

200–1000ms

Skeleton preferred.

1000ms+

Skeleton

+

Status message.

5000ms+

Offer retry.

Provide progress where possible.

Avoid blocking spinners unless interaction cannot continue.

---

# Empty States

Every empty state answers

Why is this empty?

↓

What can I do?

↓

What happens next?

Components

Illustration (optional)

Title

Description

Primary Action

Supporting Guidance

---

# Success Behaviour

Success should feel

Professional

Reassuring

Calm

Avoid excessive celebration.

Provide the next logical action.

---

# Error Behaviour

Errors should

Explain

Guide

Recover

Never blame users.

Never expose technical implementation details.

Every error should provide a recovery path.

---

# Confirmation Patterns

Confirmation is required for

Deletion

Submission

Cancellation

Policy changes

Permanent actions

Whenever possible,

prefer Undo over confirmation dialogs.

---

# Form Behaviour

Validate early.

Explain requirements before submission.

Preserve entered data.

Auto-save where appropriate.

Support keyboard navigation.

Never clear completed forms after validation failures.

---

# Search Behaviour

Search should

Respond quickly.

Support autocomplete.

Support keyboard navigation.

Debounce requests.

Display recent searches where useful.

Provide meaningful empty results.

---

# Navigation Behaviour

Users should always know

Where they are.

Where they came from.

Where they can go next.

Support

Sidebar

Breadcrumbs

Tabs

History

Deep Links

Scroll Restoration

Focus Restoration

---

# Scroll Behaviour

Landing Experience

Storytelling

Parallax

Pinned sections

Horizontal storytelling where appropriate.

Operational Experience

Native scrolling only.

Never hijack scrolling.

Never block browser behavior.

---

# Page Transitions

Transitions communicate navigation.

Never delay users.

Operational screens

200–350ms

Landing pages

May use longer cinematic transitions.

---

# Motion Behaviour

Motion communicates

State

Hierarchy

Navigation

Relationships

Never decoration.

Animations should remain GPU accelerated.

Reduced Motion mode must disable non-essential animation.

---

# Drag and Drop

Provide

Drop indicators

Live preview

Undo when possible

Keyboard alternative where appropriate.

---

# Feedback System

Every interaction produces feedback.

Visual

Required

Audio

Optional

Haptic

Future mobile support

Feedback should occur immediately after interaction.

# Accessibility

Every interaction must support

Keyboard navigation

Reduced motion

High contrast

Screen readers

Logical focus

Accessible labels

Touch accessibility

---

# AI Implementation Rules

AI coding assistants must

Reuse documented interaction patterns.

Never invent new interaction behavior.

Never introduce inconsistent animations.

Never bypass accessibility requirements.

If a required interaction is missing,

update this specification before implementation.

---

# Anti-patterns

The following interactions are prohibited.

• Hover-only functionality

• Infinite nested dialogs

• Scroll hijacking in dashboards

• Hidden navigation

• Gesture-only interactions

• Tiny touch targets

• Auto-playing media in operational screens

• Blocking spinners for long operations

• Unexpected page movement

• Decorative motion without purpose

# Final Principle

Interaction is communication.

Every interaction should reduce uncertainty.

Every interaction should build trust.

Every interaction should respect the user's time.

If an interaction does not improve clarity, accessibility, or confidence, it should not become part of ATLAS.
